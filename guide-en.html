BSOD Analyzer — Quick Analysis Buttons Guide

After picking a .dmp file, 8 quick analysis buttons appear in the side panel. Each button runs a preset set of kd.exe commands and automatically feeds the output to AI for interpretation.

🧠 Full Triage + AI Summary Start Here

kd commands

vertarget; .bugcheck; !analyze -v; kb 100; lm t n; !irql; !sysinfo smbios; !cpuinfo

The "full scan" button. Runs the 8 most useful commands in one shot, covering: OS version, bugcheck code, detailed error analysis, call stack, loaded module list, current IRQL, hardware info (SMBIOS), and CPU details. The AI summarizes:

  • Bugcheck code and name
  • One-line root cause
  • Faulting module and driver type
  • Key evidence quotes
  • 3–5 suggested follow-up kd commands
Use this first when looking at an unfamiliar dump or under time pressure. Its output covers ~80% of common issues and guides further investigation.

🔍 !analyze -v

kd commands

.bugcheck; !analyze -v

Runs WinDbg's core auto-analysis command in isolation. .bugcheck lists the bugcheck code and four parameters (Arg1–Arg4); !analyze -v performs a deep analysis:

  • Bugcheck name and mechanism description
  • Faulting memory address, PFN
  • Faulting module (name, version)
  • Stack trace summary
  • Failure Bucket (problem fingerprint for KB matching)

The AI identifies whether the faulting module is inbox (Windows native), third-party, or a known problematic driver.

Use when you already know the general direction and want to pinpoint the faulting driver and Arg meanings. Also useful as a follow-up to Full Triage.

📚 Call Stack (kb 100)

kd commands

kb 100; !thread

kb 100 shows up to 100 stack frames at crash time, each with return address, function name (requires symbols), and the first three arguments. !thread outputs full thread info. The AI annotates each frame and:

  • Identifies the crash point (highest valid frame)
  • Marks user-mode / kernel transitions
  • Highlights any third-party driver frames
Use when !analyze -v points to a driver that looks like a "victim" rather than the "culprit" and you need to trace back the call chain.

💻 Loaded Modules (lm t n)

kd commands

lm t n

Lists all modules loaded in memory at crash time, including base address, size, name, path, and symbol status. The AI flags:

  • Third-party drivers (non-Microsoft)
  • Drivers that appear outdated or unsigned by their timestamps
  • Known high-risk categories: antivirus, VPN, RGB control, overclocking tools
  • Items worth investigating further with lmvm <module>
Use when the system has many third-party apps installed, or when the module flagged by !analyze -v has an old version.

🖥️ System / CPU / BIOS

kd commands

vertarget; !sysinfo smbios; !cpuinfo
CommandOutput
vertargetWindows OS version, build number, Service Pack, memory size
!sysinfo smbiosBIOS version/date, motherboard manufacturer and model, system serial
!cpuinfoCPU family, model, stepping, microcode version
Use when suspecting a BIOS bug or microcode issue, or when you need hardware details for a bug report.

🧮 Memory / Pool

kd commands

!vm; !poolused 2; !memusage 0
CommandOutput
!vmVirtual memory stats: total VA, committed, Paged/NonPaged Pool size and limits
!poolused 2NonPaged Pool usage by Pool Tag, sorted descending — find leak sources
!memusage 0Physical memory page summary (free, in use, transition, modified, etc.)
Use when the bugcheck is related to POOL_CORRUPTION / OUT_OF_MEMORY, or when suspecting a memory leak (BSOD only after extended uptime).

🧵 Current Thread / IRQL

kd commands

!thread; !irql; kv
CommandOutput
!threadFull thread info: TEB, state, wait chain, stack pointer
!irqlCurrent IRQL — shows the interrupt level at crash time
kvVerbose call stack with frame pointers and trap/exception frame markers
Use when the bugcheck is IRQL_NOT_LESS_OR_EQUAL, or when !analyze -v shows IRQL = 2 (DISPATCH_LEVEL) or higher, suggesting a DPC / ISR issue.

📄 Generate Markdown Report

This button runs no new kd commands. It feeds all kd outputs collected in the current session to the AI and requests a structured Markdown analysis report with these sections:

  • Bugcheck Summary (table: code, name, description, Arg1-4, Failure Bucket)
  • Root Cause (one-line summary)
  • System Information (manufacturer, model, BIOS, CPU, OS)
  • Faulting Component (module, symbol, driver type)
  • Call Stack (annotated per-frame)
  • Evidence (raw kd output quotes)
  • Recommendations (driver version, KB number, BIOS URL, registry settings)
  • Confidence & Residual Uncertainty

Missing fields are filled with "N/A" — the AI will not fabricate values. The report is also automatically saved as a .md file and its folder is opened in File Explorer.

⚠️ If no other buttons have been run in the current session, you will be prompted to run at least one analysis step first.

📋 Recommended Workflow

1. Pick .dmp ↓ 2. 🧠 Full Triage + AI Summary ← Required — get a global overview ↓ 3. Optionally follow AI suggestions: ├─ Suspect driver issue → 💻 Loaded Modules ├─ Need deeper call stack → 📚 Call Stack ├─ Possible memory leak → 🧮 Memory / Pool ├─ IRQL-related crash → 🧵 Current Thread / IRQL └─ Verify hardware specs → 🖥️ System / CPU / BIOS ↓ 4. 💬 Free-form follow-up questions ↓ 5. 📄 Generate Markdown Report ← Final step

Outputs accumulate across the session — later buttons and follow-up questions can all reference previously collected data without re-running commands.
