🩺 BSOD Analyzer

AI-powered Windows kernel crash dump (MEMORY.DMP / BSOD) analyzer

How it works
  • Pick a .dmp in the side panel → a Chrome native messaging host runs kd.exe locally.
  • The host uses your configured symbol path + proxy; no HTTP server is involved.
  • kd output is sent to GNAI (gpt-4o by default) with a WinDbg-expert system prompt.
  • GNAI key + model live in the header (🔑 / model dropdown). Tool paths live under ⚙️ Settings.
Setup
  • Install Debugging Tools for Windows (ships with the Windows SDK) — gives you kd.exe.
  • Load this extension unpacked in chrome://extensions and copy its ID.
  • Register the native messaging host (one-off, per user, no admin): 
    cd bsod-analyzer\native_host
powershell -ExecutionPolicy Bypass -File install.ps1 -ExtensionId <EXT_ID>
  • Open the side panel → click 🔑 and paste your GNAI_TOKEN (JWT from gnai.intel.com).
  • (Optional) ⚙️ to tweak kd.exe path, _NT_SYMBOL_PATH, or Proxy.
Quick-Analysis Buttons
  • Full Triage + AI Summary — runs vertarget; .bugcheck; !analyze -v; kb 100; lm t n; !irql; !sysinfo smbios; !cpuinfo.
  • !analyze -v — focused bugcheck interpretation.
  • Call Stack (kb 100) — annotated stack walk.
  • Loaded Modules (lm t n) — flags third-party / suspicious drivers.
  • System / CPU / BIOS — platform context.
  • Memory / Pool — !vm, !poolused 2, !memusage.
  • Thread / IRQL — !thread, !irql, kv.
  • Generate Markdown Report — structured report from accumulated kd output.
Privacy: Dumps never leave your machine. The native host runs kd.exe locally over stdio — no sockets, no localhost ports. Only the kd.exe text output is sent to GNAI.
